# 验证记录

本文汇总 2026-11-18 至 2026-11-19 做过的测试和结果。所有测试都在同一台机器上用测试脚本跑，没有 CI。

**环境**

- 主机：Apple Silicon Mac，macOS 26。
- Xcode 27.2（27B52），iOS 27.2 模拟器 runtime，模拟器机型 iPhone 18 Pro（arm64）。
- 工具链：README 里钉死的那一套。Kotlin/Native 2.5.255-SNAPSHOT（带本仓库的热重载补丁）、自建的 LLVM + libKaldo、
  Compose Multiplatform jb-main `ee243c321` 一系（runtime 1.13.0-beta01）。测试期间补丁和 libKaldo 有过几次小改，
  各节注明了日期或对应的接口版本（`interfaceVersion`）。

**口径**

- **延迟 = 保存 → 新代码的首帧。** 测试脚本改写源文件里的一个标签后，立刻触发热重载（单文件 demo 调用 reload 脚本，
  Gradle 示例执行 `./gradlew hotReload`），从这一刻开始计时，到 app 控制台日志里第一次出现带新标签的渲染行为止。
  包含编译、合并、发送、JIT 加载和重组；不含文件监听。
- **“同一 PID”**：整组测试里 app 进程没有重启（进程号不变），页面和 `remember` 状态是在原进程里保留下来的。
- 每一轮都检查：新标签上屏、页面和计数器没变（多模块时还要求另一个模块的标签没变）、PID 没变。

## 4. 异常穿过 JIT 代码

Compose 在翻页时 dispose 节点，会抛出并捕获异常，这些异常要穿过 JIT 加载的代码。iOS 模拟器（arm64）的编译产物只有
compact unwind、没有可用的 `__eh_frame`，所以 libKaldo 在启动时由 compact unwind 合成 `__eh_frame` 并整段注册
（启动时 `KALDO_SYNTH_EH_FRAME=1`，打包时 `KALDO_KEEP_COMPACT_UNWIND=1`）。

| 测试内容 | 次数 | 结果 | 备注 |
|---|---|---|---|
| 启动探针：`main()` 里让异常穿过 6 层 JIT 帧后接住，打印 `EH OK eh-probe` | 每次启动 | 第 3 节 EH 合成打开的冷启动全部出现，温重启后也出现 | 缺了就判失败：启动脚本退出码 2，不当偶发崩溃去重试 |
| 启动时 EH 表自检 | 每次启动 | 约 12.6 万条 FDE、约 3,800 条 LSDA；越界 0，personality 无法解析 0；全部整段注册 | Gradle 插件冷启动 10 次逐次检查 |
| 反向：启动时不设 `KALDO_SYNTH_EH_FRAME` | 2 | 探针按预期失败：没有 `EH OK`，进程退出；启动脚本报 `EH probe failed`，退出码 2，0 次重试 | 说明探针能抓住 EH 回归 |
| 反向：`KALDO_SYNTH_EH_FRAME=0` | 1 | 同上，退出码 2 | 早先版本只看变量是否存在，设成 0 也会合成；已改成按值判断 |
| 真实点击翻页（单文件 demo） | 1 组 | 通过：Next → 第 2 页，`+` ×3 → 计数器 3，Back → 第 1 页，同一 PID | 没有 `ModifierNodeDetachedCancellationException` |
| 真实点击翻页（Gradle 示例，参考脚本） | `+` ×3，Next/Back 3 个来回 | 通过：页面 0 → 1 → 0，计数器保持 3，同一 PID，无崩溃 | 用 AXe 在模拟器上点击 |
| 真实点击翻页（Gradle 插件） | 同上 | 通过：崩溃 / 未捕获异常 0 行 | 见第 7 节 |

## 5. 兼容性分类器与温重启

热重载在发送补丁前比较新旧 klib 的元数据和 IR：能热替换的直接发送；类字段布局、函数签名、inline/suspend 函数正文、
新增顶层属性这几类改动会被拦下，自动重新打包、重启 app，并用启动参数把页面和计数器恢复回来（温重启）。
整张矩阵一条命令跑完：热替换用例要求截图变化，温重启用例要求截图和改动前相同（裁掉状态栏后比较）。
最近一次：2026-11-19，接口 v8。

| 测试内容 | 次数 | 结果 | 备注 |
|---|---|---|---|
| 可热替换的 6 类：改文案、改颜色、改 `if` 分支（再改回）、普通函数体、增 composable、删 composable | 7 | 7/7 | 同一 PID，新内容上屏，截图变化 |
| 准备步骤（也走热替换）：新增类、新增函数、新增 inline 函数、新增 suspend 函数 | 4 | 4/4 | 同一 PID；给后面的温重启用例准备 |
| 需温重启的 5 类：类字段布局、函数签名、inline 函数正文、suspend 函数正文、新增顶层属性 | 5 | 5/5 | 打印 `WARM <类别>` 和原因 → 重新打包、重启 → 回到第 2 页、计数器 3，截图和改动前相同；PID 按预期改变 |
| 温重启后真实点击：Back、`+`、Next、Back | 1 | 1/1 | 计数器 3 → 4，两次翻页，同一 PID，日志里没有崩溃或未捕获异常 |
| **合计** | **17** | **17/17** | 同一矩阵之前还完整通过过两次（17/17；加点击用例之前 16/16） |
| `reload --no-warm`（只拦截、不重启） | 2 | 2/2 | 打印原因，退出码 3，补丁没发送，同一 PID |
| 温重启耗时 | 2 | 63.9 s（打包 53.6 s + 重启到恢复页面 10.3 s）；缓存更热时 60.7 s（54.1 s + 6.6 s） | 每次都重跑完整打包，所以远慢于热替换的 4–5 s |
| 温重启耗时（首发后提速，参考脚本） | 9 | 15.8–22.7 s，中位 16.4 s（打包 10.4–10.9 s + 重启到恢复 5.4–12.0 s）；同机提速前 45.3–47.3 s（打包 39.6–41.0 s） | `example-gradle/accept-warm-speedup.txt`；同一版本 B4 回归 17/17（`accept-warm-b4.txt`） |

- 温重启只恢复页面和计数器（参考 app 把它们写进 `Documents/hr-state.json`，重启时用 `--hr-state` 参数带回），
  其它 `remember` 瞬态（动画进度、滚动位置等）不恢复。
- 分类器偏保守：认不出的类成员变化也按温重启处理，只改构造函数的默认参数值也会温重启。宁可多重启一次，不冒错布局的风险。
- 本节测试都通过参考脚本 `hotreload.sh` 运行；Gradle 插件还没有接入分类器。

## 8. release 构建

**“release 零改动”的意思**：热重载相关的改动都在环境开关和 split 编译分支后面，release 构建不打开这些开关、不走 split，
产物不应该有任何变化。Gradle 插件只在自己的 hot reload 任务组里新增任务，不改已有的任务、配置和变体。

**验收口径**：各段大小和符号表必须与基线完全一致；`__text` 的哈希必须落在基线构建出现过的集合里。
不用整文件 md5，原因见下表。

| 测试内容 | 次数 | 结果 | 备注 |
|---|---|---|---|
| 打补丁前后的编译器各编同一个小程序（不走 split） | 3 + 3 | `__text` 362,880 字节、符号 6,014 个，前后完全一致 | 整文件差 320 字节，在 DWARF / 字符串表（缓存路径长度不同） |
| 同一个编译器连编两次 | 2 | 整文件 md5 不同（709 字节，在 `LC_UUID`、`__objc_methname`、`__LINKEDIT`） | 所以整文件 md5 不能当验收口径 |
| 应用插件前后的 Gradle 任务列表 | 自动化测试 | 去掉 hot reload 任务组后 `tasks --all` 完全一致 | |
| 完整流程：记基线 → 热重载会话（打包、启动、9 次热替换，守护进程和 app 都在运行）→ 在 Gradle 里重编 release 比对 → 在 Gradle 外用 `env -i` 复现比对 | 1 | 通过：61,715 个符号、41 个段的大小与基线一致，`__text` 在基线集合里 | 记基线时连续构建两次就见到了两种 `__text` |
| 口径灵敏度：记基线后不改源码比对两次 → 改一处源码 → 改回 | 1 | 两次通过；改源码后失败（`__text` 不在集合里，`__DATA_CONST,__const` 大小 1,533,584 → 1,533,632）；改回后通过 | 说明口径能发现真实改动 |
| 对照：不应用插件、没有守护进程、app 没运行 | 5 | 段大小、符号表 5 次都相同；`__text` 两种哈希（3 次 + 2 次） | 不可逐位复现来自工具链本身 |
| 对照：应用插件、热重载会话进行中 | 5 | 同样的两种哈希，没有超出上面的集合 | release 编译进程里没有任何热重载环境变量或参数，没有向守护进程发请求 |
| 对照：会话结束后 | 5 | 同样的两种哈希 | |

**已知的不确定性**：release 产物本身不可逐位复现。原因（REPORT §28）：Apple 链接器给 `_objc_msgSend` 建了两个 GOT 条目，
先后顺序每次链接可能不同，`__text` 里 78 处读取的偏移随之变化；两个条目绑定同一个地址。`scripts/release-text-digest.py` 按绑定的符号
归一化 GOT 读取后，5 次构建的两种变体得到同一个摘要（`example-gradle/accept-2b.txt`）。另外 release 比对必须固定 `-module-name`：
不固定时模块名每次构建都变，它会进入 cinterop 桥接符号名，改变符号顺序和 `__text`，同样与热重载无关。

## 未覆盖

- **真机**：没做。只在 iOS 模拟器（arm64）、macOS arm64 主机上测过。
- **长会话**：最长测到单个 app 进程连续运行 3.5 小时（工具链 .4，发送到首帧约 0.9 s 涨到 1.86 s）。工具链 .6、EH 合成和强制重组都开，
  3 小时 341 次 reload 全部成功、内存不增长，但 app 内的加载耗时和 reload 次数成正比（app 模块 0.3 s → 3.2 s，REPORT §30.1），
  重启进程后恢复；慢在加载的哪一步未定位。超过 3.5 小时的会话没测。
- **https 下载**：预构建工具链只跑通了本地 `file://`；从私有 GitHub Release（走 API）和 GitHub Packages（带 token）下载的代码写了，
  但没对真实服务器跑过。工具链也还没正式发布。
- **并发保存**：上一次热重载还没完成时再次保存，行为没有验证（app 里一次只处理一个请求）。
- **其他机器**：所有测试都在同一台机器、同一版本的 Xcode 和模拟器 runtime 上跑。没在第二台机器上从零验证；Xcode / 模拟器 runtime
  与清单不一致时的报错路径没验证；从源码构建 LLVM、Kotlin/Native、Compose 这三步没有从零复现过。
- **Gradle 插件 + 兼容性分类器**：插件还没接入分类器，第 5 节只在参考脚本上测过。
- **Info.plist 布尔值**：工具链 .5 修复，示例 app 打开 Compose 默认的严格检查启动（TECHNICAL-NOTES §1.8）；.4 及以前要关闭这个检查。
